# 프로젝트 비전 및 요구사항

## 프로젝트 개요

**database-data-analysis**는 대학 강의용으로 설계된 Docker 기반 데이터 분석 실습 환경입니다. MySQL 데이터베이스와 Python 분석 도구를 통합하여 데이터 분석 입문자가 복잡한 환경 설정 없이 즉시 실습을 시작할 수 있도록 지원합니다.

### 핵심 가치 제안

- **원클릭 환경 구축**: Docker Compose 한 번의 명령으로 MySQL + Jupyter Lab + Streamlit 통합 환경 제공
- **한글 완벽 지원**: NanumGothic 폰트가 사전 설정되어 matplotlib, seaborn, plotly에서 한글이 깨지지 않음
- **교육 최적화**: 실무 표준 도구(Jupyter Lab, Streamlit)와 샘플 데이터(classicmodels)로 즉시 학습 시작
- **클라우드 확장성**: Google BigQuery 연동 준비로 로컬→클라우드 학습 경로 제공

## 목표 사용자

### 주 사용자: 데이터 분석 입문자

**프로필**:
- 학부생 (데이터베이스/데이터 분석 수강생)
- 초급 개발자 (경력 1년 미만, SQL 및 Python 기초 학습 중)
- 데이터 분석 도구 사용 경험 부족
- 환경 설정에 어려움을 겪는 비전공자 포함

**주요 시나리오**:
1. **강의 실습**: 교수가 제공한 SQL 쿼리를 Jupyter Notebook에서 실행하고 결과를 시각화
2. **과제 제출**: pandas로 데이터를 분석하고 matplotlib으로 차트를 생성하여 리포트 작성
3. **자가 학습**: classicmodels 샘플 데이터베이스로 JOIN, GROUP BY, 서브쿼리 연습
4. **프로젝트 개발**: Streamlit으로 간단한 대시보드를 만들어 데이터 시각화 포트폴리오 구축

### 부 사용자: 강사/조교

**프로필**:
- 대학 강의 담당 교수 및 조교
- 학생들에게 일관된 실습 환경 제공 필요
- Docker 기본 지식 보유

**주요 시나리오**:
1. **환경 배포**: 학생들에게 docker-compose.yml 공유로 동일한 환경 제공
2. **예제 관리**: notebooks/ 디렉토리에 주제별 실습 노트북 배포
3. **과제 검증**: 학생이 제출한 SQL 쿼리와 분석 코드를 동일한 환경에서 검증
4. **문제 해결**: 학생의 환경 문제 발생 시 reset 스크립트로 신속 초기화

## 해결하는 문제

### TOP 3 핵심 문제

#### 1. 환경 설정의 복잡성 (우선순위: HIGH)
**현재 상태**:
- 학생들이 각자의 OS(Windows, Mac, Linux)에서 MySQL 설치 시 버전 차이, 권한 문제, 포트 충돌 등으로 수업 시작 전 1-2주 소요
- Python 가상환경 설정과 패키지 의존성 관리에 어려움 (특히 비전공자)
- 한글 폰트 설정 실패로 시각화 결과에 깨진 문자 표시

**목표 상태**:
- `docker-compose up` 한 번으로 MySQL 8.0 + Python 3.11 + 모든 필요 라이브러리 자동 설치
- 한글 폰트 사전 설정으로 추가 작업 없이 한글 차트 생성 가능
- 플랫폼 독립적: Windows/Mac/Linux 모두 동일한 환경

**측정 지표**:
- 환경 설정 소요 시간: 2주 → 10분 이내
- 학기 초 환경 관련 문의: 주당 20건 → 5건 이하
- 첫 실습 참여율: 70% → 95%+

#### 2. 일관성 없는 학습 환경 (우선순위: HIGH)
**현재 상태**:
- 학생마다 다른 MySQL 버전(5.7, 8.0), Python 버전(3.8, 3.10, 3.11) 사용
- 강사의 예제가 학생 환경에서 작동하지 않는 경우 빈번 (특히 인증 방식 차이)
- 일부 학생은 로컬 설치, 일부는 클라우드 서비스 사용으로 학습 경험 불균등

**목표 상태**:
- 모든 학생이 MySQL 8.0 + Python 3.11 고정 버전 사용
- classicmodels 샘플 데이터베이스 사전 로드로 동일한 학습 데이터 보장
- Jupyter Lab + Streamlit 통합 환경으로 학습→프로젝트 연속성 확보

**측정 지표**:
- 환경 불일치로 인한 수업 중단: 주당 3회 → 0회
- "제 컴퓨터에서는 안 돼요" 문의: 주당 15건 → 2건 이하
- 과제 제출 시 실행 불가능 코드 비율: 30% → 5% 이하

#### 3. 실무 도구 경험 부족 (우선순위: MEDIUM)
**현재 상태**:
- 학생들이 단순 IDE(IDLE, Spyder)에서만 코드 실행, 실무 표준 도구 경험 없음
- 데이터 시각화를 정적 이미지로만 경험, 대시보드 개념 부재
- 로컬 환경에만 의존, 클라우드 데이터 웨어하우스 학습 기회 없음

**목표 상태**:
- Jupyter Lab으로 탐색적 데이터 분석(EDA) 워크플로 학습
- Streamlit으로 인터랙티브 대시보드 개발 경험 제공
- BigQuery 연동 준비로 클라우드 환경 학습 경로 오픈

**측정 지표**:
- Jupyter Notebook 과제 제출률: 0% → 80%+
- Streamlit 기반 프로젝트 완성률: 0% → 50%+
- BigQuery 연동 실습 참여 학생 수: 0명 → 학기당 10명+

## 차별화 요소

### 경쟁 대안 대비 강점

| 비교 항목 | 기존 방식 (로컬 설치) | 클라우드 서비스 (AWS RDS, Colab) | **본 프로젝트** |
|----------|---------------------|--------------------------------|----------------|
| **설치 시간** | 1-2주 (OS별 차이 큼) | 계정 생성 필요, 크레딧 관리 | 10분 (Docker만 필요) |
| **비용** | 무료 (로컬 리소스) | 유료 또는 크레딧 소진 시 중단 | 무료 (로컬 리소스) |
| **한글 지원** | 수동 설정 필요 | Colab 기본 지원 (MySQL 별도) | 사전 설정 완료 |
| **오프라인 사용** | 가능 | 불가능 (인터넷 필수) | 가능 |
| **일관성** | 낮음 (환경마다 차이) | 높음 (제공사 관리) | 높음 (Docker 이미지 고정) |
| **실무 도구 경험** | IDE만 제공 | Jupyter 제공, MySQL 별도 | Jupyter + Streamlit + MySQL 통합 |
| **확장성** | 로컬 한계 | 클라우드 확장 용이 | BigQuery 연동 준비로 하이브리드 |

### 핵심 차별점

1. **All-in-One 교육 환경**: MySQL + Jupyter + Streamlit + 한글 폰트를 단일 docker-compose로 제공
2. **Zero Configuration**: `docker-compose up` 후 즉시 실습 가능, 추가 설정 불필요
3. **교육 최적화 데이터**: classicmodels 샘플 DB가 사전 로드되어 강사가 별도 데이터 준비 불필요
4. **하이브리드 학습 경로**: 로컬 환경에서 시작하여 BigQuery로 클라우드 전환 가능

## 제약사항 및 가정

### 기술적 제약
- Docker Desktop 설치 필수 (학생 PC에 관리자 권한 필요)
- 로컬 리소스 의존 (메모리 부족 시 성능 저하 가능)
- BigQuery 사용 시 Google Cloud 계정 및 크레딧 필요 (선택사항)

### 비즈니스 제약
- 대학 강의 용도로 설계, 프로덕션 환경 부적합
- 보안 설정이 교육용으로 간소화 (root 비밀번호 1111, 공개 포트)
- 상업적 사용 고려 없음 (MySQL Community Edition, 오픈소스 라이브러리)

### 가정
- 학생들이 Docker Desktop 설치를 완료했거나 강의 시간 내 설치 지원 가능
- 강사가 Git을 통해 예제 노트북 및 데이터를 배포할 수 있음
- 학생 PC가 인터넷 연결 가능 (초기 Docker 이미지 다운로드)
